## 2. Graph algorithm (그래프 · 다익스트라)

### 무엇을 하나요?

- 공항(또는 지점) **좌표 데이터**를 읽고, 지점 간 **가중 무방향 그래프**를 만듭니다.
- 변의 가중치는 위·경도로부터 **`haversine` 패키지**로 구한 **지표상 거리(예: 미터)** 에 가깝게 둡니다(구면 대원 거리).
- **`Dijkstra`** 로 최단 경로(또는 목표 도착 시 조기 종료에 가까운 우선순위 큐 탐색)를 구현하고, **부모 포인터**로 경로를 복원합니다.
- **“나쁜 기상” 영역**을 다각형 등으로 두면, 그 구간을 통과하는 간선 비용을 키우거나 우회하도록 **`dijkstra(G, start, goal, bad_regions)`** 형태로 실험합니다.
- `represent(...)` 로 **지도상 경로·금지 구역**을 함께 그립니다.

### 코드에서 자주 나오는 이름

| 이름 | 역할 |
|------|------|
| 그래프 클래스 | 정점·간선·가중치 추가, 이웃 조회 |
| `dijkstra` | 시작·목표, `bad_regions` 옵션 |
| `make_path` | 부모 배열로부터 경로 리스트 |
| `calculate_path_distance` | 경로 총 거리 |
| `represent` | 데이터프레임 + 그래프 + 경로 + bad 영역 시각화 |


## 2.1. 왜 “그래프”로 모델링하는가?

### 문제의 형태

- 입력은 **표 형태 데이터**(공항 이름, IATA 코드, 위도·경도)입니다.
- 과제에서 풀고 싶은 질문은 보통  
  **“이 공항들 사이에서, 주어진 연결만 따라 갈 때 A에서 B까지 얼마나 짧게 갈 수 있는가?”**  
  입니다.

이를 컴퓨터가 다루기 좋은 형태로 바꾸면 다음 두 가지가 필요합니다.

| 필요한 개념 | 역할 |
|-------------|------|
| **정점(vertex)** | 각 공항(또는 지점) 하나 |
| **간선(edge) + 가중치(weight)** | “두 공항이 직접 이어져 있다”는 정보와, 그 구간의 **비용(거리)** |

이 구조가 곧 **가중 그래프(weighted graph)** 입니다. 좌표만 있다고 해서 자동으로 “모든 쌍”이 이어지는 것은 아니고, **어떤 공항 쌍이 직항/노선으로 연결되는지**는 과제·시나리오에서 정해 줍니다. 노트북에서는 먼저 **인접 리스트** 형태로 그 연결 관계를 적어 넣고, 그 위에 거리를 얹습니다.

### 그래프를 만들지 않으면?

- 좌표만 있으면 **유클리드 직선 거리**는 계산할 수 있지만, **“중간에 반드시 거쳐야 하는 공항·허용된 구간”** 같은 **이산적 제약**을 반영하기 어렵습니다.
- 최단 경로를 **체계적으로** 찾으려면 “어디에서 어디로 갈 수 있는지”를 명시한 **그래프 + 최단 경로 알고리즘**이 맞습니다.

## 2.2. 그래프 자료구조: 무엇을 어떻게 저장하는가?

### `Graph` 클래스 (노트북)

참고: [Bogotobogo 그래프 자료구조 예제](https://www.bogotobogo.com/python/python_graph_data_structures.php) 스타일을 따릅니다.

- **`self.graph`**: 정점 이름 → **이웃 정점 이름들의 리스트** (인접 리스트).
- **`self.weight`**: 정점 `u` → `{ 이웃 v: 가중치 }` 딕셔너리.  
  즉 **무방향**을 표현하려면 `u`의 이웃으로 `v`가 있고, `v`의 이웃에도 `u`가 있어야 하며, **양쪽 `weight`에 동일 거리**가 들어가야 합니다(노트북의 토이 연결은 수동으로 맞춰 둠).

주요 메서드:

| 메서드 | 하는 일 |
|--------|---------|
| `add_vertex(start, end_list)` | `start`의 이웃 목록을 설정하고, `add_edge`로 가중치를 붙일 준비 |
| `add_edge(node, weights)` | `graph[node]`의 이웃 순서와 같은 순서로 `weights`를 매칭해 `weight[node][이웃]=값` 저장 |
| `get_vertices(node)` | 해당 정점의 이웃 리스트 |
| `print()` / `get_graph_dict()` | 디버깅·출력용 |

### 연결 관계(토이 예)와 가중치 부여

1. **먼저** 공항 코드로 **어떤 쌍이 간선인지**를 `add_vertex`로 적습니다.  
   (예: `CJU`—`ICN`, `CJJ`, `PUS` 등. 과제에서 주어진 네트워크 가정.)
2. **그다음** 각 간선에 대해 `airport_df`에서 두 공항의 `(Latitude, Longitude)`를 꺼내 **`haversine(p1, p2, unit='km')`** 으로 **대원 거리(km)** 를 계산합니다.
3. 구한 리스트를 `add_edge`에 넘겨 **가중 무방향 그래프**를 완성합니다.

여기서 **Haversine**을 쓰는 이유는, 위·경도는 구면 위의 점이므로 **평면 거리가 아니라 지구 표면에 가까운 거리**를 쓰기 위함입니다(루트 README·유전 TSP 문서와 같은 논리).

### 다익스트라용으로 `g` 변환

`Graph` 객체는 출력·시각화에 쓰기 좋고, 다익스트라 루프에서는 **정점 → `(이웃, 거리)` 쌍들의 집합** 형태가 편합니다. 노트북은 `get_graph_dict()`로 문자열을 만든 뒤 `eval`로 튜플을 복원하고, 이를 **`g`** 라는 딕셔너리로 두어 `dijkstra(g, ...)`에 넘깁니다.  
(실무에서는 `eval` 대신 처음부터 `(이웃, 가중치)` 튜플로 구성하는 편이 더 안전합니다.)

## 2.3. 다익스트라(Dijkstra) 알고리즘

### 정의(이 노트북이 가정하는 조건)

- 그래프의 간선 가중치는 **0 이상**(노트북에서는 거리 km → 자연스럽게 양수).
- **음의 간선이 없을 때**, 한 **시작점**에서 다른 모든 정점까지의 **최단 거리**를 구하는 대표 알고리즘이 다익스트라입니다.
- 이 구현은 **목표 정점 `goal`이 정해져 있으면**, 그 정점을 처리한 뒤 **루프를 끊는** 형태로 **조기 종료**에 가깝게 동작합니다(목표만 필요할 때 유리).

### 왜 필요한가?

- “모든 가능한 순서를 다 나열”하면 지점이 늘어날수록 **지수적으로** 커집니다.
- 다익스트라는 **우선순위 큐**로 “지금까지 가장 짧게 도달한 정점”부터 확정해 가며, **양의 가중치**에서는 각 간선을 합리적인 순서로 **한 번씩** 완화(relaxation)하면 됩니다.

### 노트북에서의 구현 흐름 (세부)

구현 참고: [qpwo gist — PriorityQueue 기반 Dijkstra](https://gist.github.com/qpwo/cda55deee291de31b50d408c1a7c8515) 를 구조 아이디어로 명시합니다.

1. **자료 구조**
   - `from queue import PriorityQueue` 로 **최소 힙 성격의 큐** `todo` 사용.
   - `cost[v]`: 시작점에서 `v`까지 **현재까지 찾은 최단 거리 추정값**.
   - `parent[v]`: 최단 경로 트리에서 `v`의 **바로 이전 정점**(경로 복원용).
   - `visited`: 이미 **확정 처리한** 정점 집합(이 구현은 **lazy deletion**: 큐에 남은 옛 항목은 `visited`로 스킵).

2. **초기화**
   - `cost[start] = 0`, `parent[start] = None`.
   - `todo.put((0, start))`.

3. **메인 루프**
   - 큐에서 `(누적거리, vertex)` 꺼냄.
   - 이미 `visited`에 있으면 **continue**(낡은 후보 제거).
   - `vertex`를 `visited`에 넣음.
   - **`vertex == goal`이면 break** — 목표만 필요할 때 여기서 종료.
   - 각 이웃 `neighbor`에 대해:
     - 이미 `visited`면 스킵.
     - **`new_cost = cost[vertex] + distance`**.
     - **나쁜 기상(`bad_regions`)** 이 있으면 아래 4번을 먼저 수행해, **해당 간선을 아예 쓸 수 없으면** 이 이웃으로의 이완을 하지 않음.
     - `new_cost < cost.get(neighbor, inf)` 이면  
       `cost[neighbor] = new_cost`, `parent[neighbor] = vertex`,  
       **`todo.put((new_cost, neighbor))`**.

4. **나쁜 기상 구역과 간선 제외**

   - `calculate_line_equation(a, b)`: 두 공항 좌표 `(경도, 위도)` 를 잇는 **선분을 아주 잘게 샘플링**한 점들 `points`를 만듭니다.
   - `is_point_in_bad_area(points, bad)`: `bad`는 **축에 평행한 직사각형**을 대표하는 점 네 개로 보고, 샘플 점이 그 **축정렬 bounding box** 안에 하나라도 들어가면 `True`.
   - **어떤 `bad`라도** 선분이 그 구역을 **가로지른다고 판단되면**, 그 간선은 **`continue`로 완전히 제외**됩니다.  
     (가중치를 키우는 **페널티 모델이 아니라**, 이 과제에서는 **금지 구간**에 가깝게 구현되어 있습니다.)

5. **반환**
   - `return parent` — 시작에서 각 정점까지의 **최단 경로 트리**를 부모 포인터로 표현.

### 경로 복원·거리 합산

| 함수 | 역할 |
|------|------|
| `make_path(parent, goal)` | `goal`에서 `parent`를 따라 거슬러 올라가 리스트를 만들고 **뒤집어** `start → … → goal` 순서로 만듦. 목표 도달 불가면 `None` 처리. |
| `calculate_path_distance(graph, path)` | 경로에 나온 연속한 두 정점마다 `graph`에서 해당 간선 가중치를 찾아 **합산**. |

### 시각화 `represent(data, graph, path, bad)`

- `data`: 공항 테이블(산점도 + 이름 라벨).
- `graph`: 전체 간선을 **검은 점선**으로 표시.
- `path`: 최단 경로 간선만 **빨간 실선**.
- `bad`: **빨간 사각형** 패치로 “나쁜 기상” 영역 표시.

## 3. Divide and conquer (분할 정복)

### 무엇을 하나요?

- **평면 위 점들**의 **볼록 껍질(convex hull)** 을 **분할 정복**으로 구합니다.
- 점 생성 조건: **서로 다른 x**, **서로 다른 y**, **일직선상 세 점 없음(비공선)** 등으로 과제 조건을 맞춥니다.

### 흐름 (노트북 구조)

1. **Divide:** x 좌표로 정렬한 뒤 **반평면으로 분할** (`separate_half_planes` 등).
2. **Conquer:** 각 쪽에서 **작은 볼록 껍질** 생성 (`generate_convex_hull`, 방향 판별 등).
3. **Merge:** 두 볼록 껍질을 **상·하 접선** 아이디어로 합치는 단계 (`upper_lower` 등).
4. 결과를 **matplotlib**으로 표시.
